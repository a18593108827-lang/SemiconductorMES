## 学习资料沉淀（二）：Loop Engineering（循环工程）学习文件夹
- **背景**：用户追问"LOOP 工程是什么意思"，要求调研 + 架构师视角分析 + 大厂面试题讲解
- **核实结论（多源交叉，一手来源已定位）**：**概念真实存在**，非用户记错 —— 英文名 **Loop Engineering**，中文"循环工程"，由 **Addy Osmani（Google Cloud AI Director）2026-06-07 在个人博客命名并系统化**（O'Reilly Radar 2026-06-22 经授权转载）；同期 Cobus Greyling 开源 `cobusgreyling/loop-engineering`（CLI：loop-init/loop-audit/loop-cost）；IBM Think 2026-07-17 出词条。点火者 = Peter Steinberger + Boris Cherny（Claude Code 负责人）
- **核心定义**：*"replacing yourself as the person who prompts the agent. You design the system that does it instead."*（用一个你设计的系统取代你自己作为打 prompt 的人）
- **四层演进（关键心智模型，每层包裹前一层）**：Prompt（2022-24，怎么问）→ Context（2025，给它看什么）→ **Harness（2026 初，单次运行的环境）**→ **Loop（2026.06，谁决定何时再 prompt/何时停/怎么证明做对了）**
- **五积木 + 一记忆**：Automations（心跳·调度发现+分类）/ Worktrees（隔离·并行不踩脚）/ Skills（固化知识）/ Connectors（MCP 接真实工具）/ Subagents（**maker/checker 分离**）/ **Memory=脊柱**（"the agent forgets; the repo doesn't"）。Codex app 与 Claude Code 均已内建全部原语
- **血脉（机制 5 年、名字几个月）**：ReAct 2022 → Reflexion 2023（Actor/Evaluator/Self-Reflection + 情节记忆）→ AutoGPT 2023 → Anthropic《Building Effective Agents》2024.12（evaluator-optimizer / orchestrator-workers）→ 2026.06 命名
- **产出**：`学习/Loop工程/`（8 个 md，同 ReAct 文件夹风格）；含 01 定义命名史 / 02 四层演进 / 03 五积木详解 / 04 架构师视角 / 05 风险与边界 / 06 面试题 / 07 术语速查；并在 `学习/ReAct-Agent/README.md` 加了「续篇」交叉链接
- **04 架构师视角的增量结论（我的判断，非原文）**：① Loop 是**控制系统**不是流程编排 → 设计前必答三问（目标可机械验证吗/谁判停/错了怎么收拾）② **分层退出四出口必须叠加**：验证器 + 迭代硬上限 + 预算 + **无进展检测**（最后一条最易漏）③ **验证层级：确定性验证（测试/类型检查/编译/lint）> LLM 自评**，"gold standard" ④ **三层节奏**：agentic（秒-分，该自动化）/ developer（分-时）/ external（时-周）—— **选错层 = 用自动化处理本该人做的产品判断** ⑤ **Loop 的成败最小可判定标准：有没有一个"能说不"的东西**（社区最强反驳：*"没有反向推力的循环，只会变成 AI 不断同意自己的装置"*）
