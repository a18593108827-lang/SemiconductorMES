## DB / ORM 细节证据
- 全局逻辑删除：`application.yml` → `id-type: assign_id`、`logic-delete-field: deleted`、`logic-delete-value: 1`、`logic-not-delete-value: 0`；`common/BaseEntity.java:25-27` 为 `@TableLogic private Integer deleted`，**25 个实体继承它**（另 2 处自声明 `Integer deleted`：`MesEdcCollectionItem:39` / `MesFutureHold:58`）
- 全库 27 处 deleted 列**一律 tinyint**、UK **一律不含 deleted**（实测 0 例外）
- MP `logic-delete-value` **只能固定值**（反编译证据：`GlobalConfig.java:184` = `private String logicDeleteValue = "1"` 常量；`AbstractMethod.java:106` 的 `sqlLogicSet` 直接拼字面量，**无列引用解析**）
- `Integer` 装不下雪花 id（实测 `mes_lot.MAX(id)=2101886136844746754` 19 位 vs `Integer.MAX_VALUE=2147483647` 10 位 → 溢出 9.8 亿倍）
- 乐观锁先例：MesCarrier / MesDispatchReserve / MesEdcParam / MesEdcPlan / MesEdcSpec / MesEqp / MesLot；判冲突写法 `MesEdcPlanServiceImpl:141-142`
- MP `eq(col, null)` 不跳过条件：源码 `AbstractWrapper:467-470` 的 `addCondition` 只判 condition 布尔、**不判 val 是否 null**
- 判重先例 = `selectCount(…)` + `AssertUtil.isTrue(count == 0, "……已存在")`（`AuthServiceImpl:43-45`）；UK 冲突兜底 = 捕捉 `DuplicateKeyException` 沿异常链取约束名（`ComplaintPackageFacadeImpl:560-569`）
- 权限体系证据：取码 SQL 无 LIKE/前缀匹配（`SysPermissionMapper:16-26` 只判 `IS NOT NULL AND <> ''`）；`StpInterfaceImpl:20-22` 交 Sa-Token 匹配；前端 `AuthContext.tsx:72-73` = `user.permissions.includes(code)` 精确匹配；菜单树靠 `parent_id` + `perm_type`（`AuthServiceImpl:114-146`）；全仓无 `split(':')` / `startsWith('xx:')`
- 索引脚本判据：`add_frontmatter.py:100` 用 `body.startswith(b"---")`、`:138` 用 `text.startswith("---")` → 首行被写成 `\---` 时判为「无 frontmatter」，**status 流转静默失效**；启发式常推同值使 reindex 显示「无差异」→ **禁止以 reindex 无差异当作 frontmatter 完好**

## 测试 / CI 细节
- 后端 `server/src/test`（12 用例，3 类：客诉包导出装配 / 上限生效值 / format 白名单；`cd server && mvn -o test`）
- 前端 `web/src/**/*.test.tsx`（vitest + jsdom + Testing Library；`cd web && npm test`；首条 = EVAL-0001 抽屉并发下载重入 2 用例）
- `.github/workflows/ci.yml` 三闸门：后端 `mvn -B test`、文档「reindex 后 `git diff --exit-code docs/INDEX.md`」、前端 `npm ci && npx tsc -b && npm test`
- 测试**不依赖 DB/Redis/网络**；npm registry 本机**直连可达**，无需代理
- CI 约定（2026-09-24，EVAL-0002 回流）：① 被 CI 调用的脚本**禁止硬编码绝对路径**（按 `__file__` 推断仓库根）② 被 `git diff --exit-code` 比对的生成物**禁止含 `date.today()`** 等时钟输入——「同一天跑得通」≠ 幂等 ③ 改 CI 步骤后**必须在真实 runner 验证**，本地通过不算 ④ **重跑旧 commit 不会变绿**（实测 `74fc5da` 重跑 4 次、`0fffa61` 3 次仍红），须推新 commit ⑤ public 仓库 Actions 免费，单 run 约 25–33 秒，一次 push 多 commit 只触发 1 次
- 踩点：**`@JsonTest` 不能加载 `MesApplication`**（全量扫描带入 MyBatis mapper → `Property 'sqlSessionFactory' or 'sqlSessionTemplate' are required`）；改法 = 内嵌最小 `@SpringBootConfiguration` + `@EnableAutoConfiguration` + `@Import(JacksonConfig.class)`
- 踩点：AssertJ 比较 `List<int[]>` **恒不等**（数组无值语义 equals）→ 用 `List<Integer>`
- 踩点（前端测试三连）：① `user.click` 连点**测不到同步 ref 闸门**（disabled 挡住第二次）→ 竞态用同一 `act()` 内 `dispatchEvent(new MouseEvent('click'))` 连发；② `Button` loading 时用「处理中…」**替换 children**（可访问名会变）；③ vitest 未开 `globals` 时 RTL **不自动 cleanup** → setup 里显式 `afterEach(cleanup)`
- 反向验证实例：Doc-4 用「把 `setTimeLocal` 移到 `putNextEntry` 之后」确认用例变红

## 其它踩点
- 需要「改配置才能验」的分支：**不**改 `application.yml`、**不**重启用户实例，改命令行参数起第二实例（如 `java -cp target/classes com.mes.MesApplication --server.port=18080 --mes.complaint-package.enabled=false`，共享 MySQL/Redis）；前提确认启动不执行 DDL 且初始化器幂等。Git Bash 里 `nohup ... &` 起的服务会随 tool 调用结束被回收，长驻须用后台任务
- `LocalDateTime` JSON 形状取决于**容器** ObjectMapper——Spring Boot 自动配置出 ISO 文本，手搓 `Jackson2ObjectMapperBuilder.json()` 出数组（`WRITE_DATES_AS_TIMESTAMPS` 未关）→ 判形状必须用真容器 Bean
- ZIP 的 DOS 时间秒字段是 `seconds/2`（解析本地头要 ×2）；`setTimeLocal` 必须早于 `putNextEntry`
- **Git Bash 的 heredoc 会吃掉 Python 代码里的反斜杠**（`re` 的 `\s` → `/s`，正则静默不匹配）→ 写脚本用 Write 落盘 `.workbuddy/tmp/` 再 `python <file>`
- 新写的 md 可能被 IDE/格式化器改造（实测 `docs/方案/MES-厂型选型分析.md` 首行 `---` 被转义成 `\---`、行尾追加两空格 → frontmatter 解析失败 → INDEX 状态列回落）；改这类文件前先 Read，改完做字节级检查并重建 INDEX 复核
- 文档体检基线（2026-09-22）：`docs/` 105 篇 md，INDEX 收录 98 篇；`updated` 已全量补齐；**3 篇刻意不带 frontmatter**——`docs/eval/README.md`、`docs/intent/README.md`、`docs/_templates/AGENTS-骨架.md`
