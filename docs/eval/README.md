# docs/eval/ — 事故回归用例目录

每起生产事故 / 线上缺陷沉淀一条 `EVAL-{N}-*.md`（编号四位递增，EVAL-0001 起），从 `docs/_templates/EVAL-模板.md` 起稿。治理规则 G5。

**状态语义**：`active`（落档即生效）。
**启用说明**：**2026-09-22 起正式启用**（首条 = `EVAL-0001-追溯包抽屉并发下载重入.md`，验收期缺陷也落档，不区分是否已上线；**第 2 条 = `EVAL-0002-CI文档闸门失效（硬编码路径+生成物非幂等）.md`**，工具链 / 门禁自身缺陷亦落档）。**回归网已于 2026-09-23 就位**（`server/src/test` + `mvn test` + CI 三闸门，见 `docs/架构/Doc-4-plan.md`）：此后新增 EVAL 的「回归校验」段落应尽量落成用例并挂进 CI；DB / 外部依赖场景仍走「一次性探针 + 副实例」路径。

**落档口径**（2026-09-22 明确）：

| 情形 | 是否落档 |
|------|----------|
| 生产事故、线上缺陷 | 必落档 |
| 验收期 / 联调期发现的缺陷（含被用户实测抓出、修复窗口内拦下） | 落档（字段写清「性质：验收期缺陷」） |
| 探针 / 脚本自身误判 | 不落档；若暴露了口径偏差（文档或契约写得不精确）→ 落档或修正对应文档 |
| **CI / 工具链自身缺陷**（门禁脚本失效、生成物非幂等、路径不可移植等） | **落档** —— 门禁失效等于该保障**长期不存在**，性质比单点业务缺陷更重；须同时给 CI 约定补约束（见 `EVAL-0002` 回流表） |

**回流要求**：每条 EVAL 至少产出一个「防复发」回流点（模板/规则/契约/清单），只修代码不回流 = 未闭环。

规范详见 `docs/架构/MES-AI原生SDLC文档体系重构方案.md`。
