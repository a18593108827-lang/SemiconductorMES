# docs/eval/ — 事故回归用例目录

每起生产事故 / 线上缺陷沉淀一条 `EVAL-{N}-*.md`（编号四位递增，EVAL-0001 起），从 `docs/_templates/EVAL-模板.md` 起稿。治理规则 G5。

**状态语义**：`active`（落档即生效）。
**启用说明**：**2026-09-22 起正式启用**（首条 = `EVAL-0001-追溯包抽屉并发下载重入.md`，验收期缺陷也落档，不区分是否已上线）。`server/src/test` 与 CI 未建前先落档积累；建后补挂回归，作为配置与代码的回归门（Doc-5）。

**落档口径**（2026-09-22 明确）：

| 情形 | 是否落档 |
|------|----------|
| 生产事故、线上缺陷 | 必落档 |
| 验收期 / 联调期发现的缺陷（含被用户实测抓出、修复窗口内拦下） | 落档（字段写清「性质：验收期缺陷」） |
| 探针 / 脚本自身误判 | 不落档；若暴露了口径偏差（文档或契约写得不精确）→ 落档或修正对应文档 |

**回流要求**：每条 EVAL 至少产出一个「防复发」回流点（模板/规则/契约/清单），只修代码不回流 = 未闭环。

规范详见 `docs/架构/MES-AI原生SDLC文档体系重构方案.md`。
