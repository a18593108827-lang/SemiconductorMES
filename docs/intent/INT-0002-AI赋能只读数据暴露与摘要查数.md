# INT-0002 AI 赋能：只读数据暴露与摘要 / 查数

> 发起人：用户 / 记录：AI 会话 / 状态：draft
> 用法：意图只写问题与验收口径，**不写实现方案**；采纳后进入规格阶段
> 上游依据：`docs/方案/MES-AI集成产品分析.md`（L0 → L1 分期与禁止项）· `docs/方案/MES-厂型选型分析.md`（决策：AI 赋能并行）

## 1. 问题

**谁在痛**：工艺 / 设备工程师（查数要翻多张表）、质量工程师（报告与客诉摘要手写）、班组长（看板要人「读」）。

**现在什么痛**：

1. **查一个数要跨多页多表**：想知道「在制有多少」「这批卡在哪」，要自己在多个页面之间拼。
2. **报告靠手写**：班报、周报、客诉追溯摘要由人整理，一次以小时—天计；口径还不统一。
3. **Alarm / 拒出只给代码**：现场与交接班靠口头解释，新人看不懂下一步该干什么。
4. **经验不在系统里**：同类异常的历史处置散落各处，无法被检索复用。

**代价**：工程师有效工时被报表吃掉；同一问题反复问；夜班与交接班信息传递失真。

## 2. 拟议成果（验收口径）

1. **受控只读查询**：外部 Agent（或系统内嵌助手）能查询 WIP / Lot / 履历 / Hold / Alarm 等数据，且**权限与页面完全一致**——用某账号查其无权模块必须查不到；每次调用可留痕可回溯。
2. **自然语言查数**：「在制有多少」「这批卡在哪」给出的数字，与页面 / 接口同口径**可逐项核对一致**。
3. **报告 / 摘要生成**：能基于系统内既有数据起草班报、客诉追溯摘要，产出物标注「AI 起草 · 待确认」，人工确认后才对外；**摘要中每条引用都能点回原始记录**。
4. **现场不打扰**：过站路径不新增任何 AI 交互（不在现场 3 步过站里插对话窗或确认弹窗）。
5. **不越权、不改状态**：全程只读；任何写操作（Hold / Rework / 放行）仍由人在既有界面执行。

## 3. 受影响用户与系统

- 用户 / 角色：工艺 / 设备工程师、质量工程师、班组长；现场操作员仅接只读提示
- 模块：跨模块（WIP / History / Hold / Alarm / Report / Lot）——全部只读
- 表 / Facade：新增只读工具层（Tool Facade）；权限沿用 Sa-Token 原权限码

## 4. 约束

| # | 约束 | 说明 |
|---|------|------|
| A1 | AI 不得直改状态 | Lot / Hold / Recipe 状态只能由既有事务改动（沿用项目铁律） |
| A2 | 只走只读 Facade | 不直连数据库；结果附来源与查询口径 |
| A3 | 数据不出内网 | 未脱敏工艺数据禁止送外部云模型；模型可替换 |
| A4 | 先 L0 再 L1 | 必须先把数据暴露 + 审计 + 限流做出来，禁止跳过 L0 直接堆 AI 功能 |
| A5 | 现场台不引入 AI 交互 | 现场成功标准是「3 步过站」，不得被 AI 打扰 |
