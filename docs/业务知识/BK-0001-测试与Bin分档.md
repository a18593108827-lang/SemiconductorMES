# BK-0001 测试与 Bin 分档

> 主题：半导体封测的测试分档（Bin）
> 适用：封测（后道）；前道 Wafer Sort 同理
> 状态：active（已核对到「够用」的程度，未核实的点见文末）

---

## 一句话定义

**Bin = 档位 / 分拣桶**（英文就是「箱子、桶」的意思）。芯片一颗一颗测完，按测试结果被判定归入某一档（Bin1、Bin2、Bin3…），**Bin 号越小通常越好**——Bin1 是最高档。

> 换个说法：测试不是给一个"合格 / 不合格"的二元结论，而是把每颗芯片**分类**。分类结果（Bin）才是后续出货、良率、失效分析的基础数据。

---

## 为什么重要

| 视角 | Bin 数据意味着什么 |
|------|--------------------|
| **出货** | 客户规格往往是「只要 Bin1 / Bin2 可出货」。分档结果直接决定这颗能不能卖、算哪个价 |
| **良率** | 良率 = 可出货档数量 ÷ 总数。没有 Bin 汇总，就没有可信的良率口径 |
| **质量拦截** | 某一 Bin 占比突然升高，是工艺漂移的**最早信号**；应触发预警乃至 Hold / Rework |
| **失效分析** | Bin 号区分失效类型（开路、短路、参数超限…），是查根因的入口 |
| **审厂 / 客诉** | 车规客户按 IATF 16949 / VDA 6.3 / AEC-Q 审，要求「某批次分了几档、各多少颗、失效什么模式」可查可证 |

## 关键概念

### 1. 测试阶段：CP 与 FT

| 缩写 | 全称 | 中文 | 在哪测 | 判什么 |
|------|------|------|--------|--------|
| CP | Circuit Probe（Wafer Sort） | 晶圆测试 / 中测 | 晶圆上，用探针台（Prober）+ 测试机 | 每颗 die 电性能；出 Wafer Map |
| FT | Final Test | 成品测试 / 成测 | 封装完成后，用分选机（Handler）+ 测试机 | 成品功能与参数；落料到料管 / 料盘 / 编带 |

> 两个阶段的**基数不同**（CP 的基数是 wafer 上的 die 总数，FT 的基数是封装后的成品数），所以「CP 良率」与「FT 良率」不能混着谈。封装环节本身也会有损耗。

### 2. soft bin 与 hard bin（最容易混的一对）

| | 中文 | 定义 | 例子 | 数量级 |
|---|------|------|------|--------|
| **soft bin** | 软 Bin | **测试程序内部**的细分类别，回答「为什么失效」 | `34 = 漏电流超限` | 可达数百个 |
| **hard bin** | 硬 Bin | 分选机（Handler）**实际落料的物理桶**，回答「这颗现在在哪」 | `3 = 失效品料管` | 通常几十个 |

- 一个 hard bin 常**合并**多个 soft bin（所有「参数类失效」都落 hard bin 3）
- 追溯时**两个都要**：soft bin 定责，hard bin 定位实物
- 出货规格一般按 hard bin 约定（客户看不到你内部的 soft bin 细分）

### 3. Bin Map：把 Bin 号画回物理位置

把每颗的 Bin 号按它**在 wafer / strip 上的位置**画成图，就是 Wafer Map / Strip Map。价值在于**看图而不是看数**：

| 图形特征 | 通常指向 |
|----------|----------|
| 失效沿边缘一圈 | 边缘工艺不均（涂胶 / 刻蚀 / 减薄） |
| 集中在中心 | 中心区域工艺或应力问题 |
| 对角 / 条带状 | 划片、搬运、设备方向相关 |
| 散点随机 | 颗粒污染、随机缺陷 |
| 整片劣化 | 前道批次性异常或测试条件异常 |

### 4. 一张典型的 Bin 汇总（示意）

| Bin | 含义 | 颗数 | 占比 | 处置 |
|-----|------|------|------|------|
| Bin1 | 良品（最高档） | 3600 | 85.7% | 出货 |
| Bin2 | 参数次档 | 420 | 10.0% | 按客户规格（可能降级出货） |
| Bin3 | 开路失效 | 96 | 2.3% | 失效分析 / 报废 |
| Bin4 | 短路失效 | 84 | 2.0% | 失效分析 / 报废 |
| 合计 | — | 4200 | 100% | 良率 = (3600+420)/4200 = 95.7% |

> 关键洞察：**同样的总良率，Bin 构成可能完全不同**。两批都是 95.7%，一批是「Bin2 偏多」（参数漂移，可救），另一批是「Bin3 偏多」（结构性失效，危险）——处置方式相反。

## 常见误区

| # | 误区 | 纠正 |
|---|------|------|
| 1 | 以为 Bin1 永远是「良品」 | Bin 编号由测试程序 / 客户规格定义，**因厂因产品而异**，不能跨厂套用；稳妥说法是「按规格可出货档」 |
| 2 | 拿 soft bin 当 hard bin 统计 | 两者口径不同，混用会让「落料数量」与「失效原因」对不上 |
| 3 | 只看总良率，不看 Bin 构成 | 同样的良率可能是完全不同的质量问题（见上表） |
| 4 | 把 Bin 数据当"报表" | 它首先是**质量拦截的触发源**：某 Bin 超阈值就该 Hold |
| 5 | 把 CP 良率与 FT 良率混谈 | 阶段、基数、可救性都不同 |
| 6 | 以为「每颗都要有序列号才算追溯」 | 批级 + Bin 汇总 + 条级（Strip）追溯已能支撑良率、审厂与拦截；颗级序列号是更高成本的下一层 |

## 与 MES 的关系（只谈落在哪一环，不谈实现）

1. **测试结果进系统 → 与批次绑定**：这是「批次 → 分档构成」可查的前提
2. **良率口径**：Bin 汇总是一手数据，报表 / 看板里的良率应由它推出，而不是另做一套
3. **质量拦截**：Bin 超阈值 → 触发 Hold / Rework（工单式处置），并留状态变更留痕
4. **客诉 / 审厂证据链**：追溯包应能回答「这批分了几档、各多少颗、失效什么模式」
5. **边界**：MES 管「分档结果与批次绑定 + 拦截联动」；精细的良率分析与图形化 Wafer Map 分析属 YMS（Yield Management System）范畴，可后置
