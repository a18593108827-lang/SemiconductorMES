# docs/业务知识/ — 半导体业务知识库

**用途**：长期积累半导体制造的业务知识（概念、术语、行业惯例、判据），供查阅、熟悉、复习巩固。与技术实现解耦——这里回答「**是什么 / 为什么**」，不回答「我们怎么做的」。

## 与其它目录的边界

| 目录 | 回答什么 | 不写什么 |
|------|----------|----------|
| `docs/intent/` | 我们要解决什么问题（需求入口） | 行业知识、方案 |
| `docs/方案/` | 我们打算怎么做（设计与取舍） | 纯概念科普 |
| **`docs/业务知识/`** | **行业里这个概念是什么、为什么重要、怎么判** | 我们的实现方案、进度、需求 |
| `docs/模块/{模块}/` | 本系统该模块的功能 / 表 / 接口 / 已完成 | 行业通识 |

> 写知识时**不引用我们自己的表名 / 类名**（那会随实现漂移）；需要落地时在文末放「关联」链接指向对应方案或意图。

## 命名与格式

- 文件名：`BK-{N}-{主题}.md`，编号四位递增（BK-0001 起）。主题用中文名词短语，如 `BK-0001-测试与Bin分档.md`
- frontmatter 六字段（机器可读）：

```yaml
---
type: 业务知识
module:                # 留空（行业知识不专属某模块）；若确属某模块可填
status: active         # active = 落档即生效；draft = 尚未核对完
slices: []
aligns: []             # 可指向相关的 INT / 方案 / 模块文档
updated: YYYY-MM-DD
---
```

- 正文建议结构（不必逐条齐全，按主题取舍）：

| 段落 | 作用 |
|------|------|
| 一句话定义 | 先给最短的定义，再展开 |
| 为什么重要 | 对封测厂意味着什么（成本 / 质量 / 客户要求） |
| 关键概念 | 含**中英对照**；容易混的概念要对比着写 |
| 常见误区 | 踩过的坑、容易想错的地方 |
| 与 MES 的关系 | 这个知识落在系统的哪一环（不写实现） |
| 自查问题 | 3~5 问，用于复习自测 |
| 待核实 | 尚不确定或需要查标准的点，显式标注 |
| 关联 | 指向 INT / 方案 / 模块文档 |

## 复习方式

1. 打开某一篇，先只读「一句话定义」与「自查问题」，能答上就跳过正文
2. 在 `docs/INDEX.md` 里按 `type=业务知识` 检索全部条目
3. 新增知识时顺手更新下表的清单
