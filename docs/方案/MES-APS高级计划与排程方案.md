# APS（高级计划与排程）方案

> 版本：v0.1（考察稿）  
> 定位：**独立系统**，后续建设；本期 MES 不内嵌 APS  
> 原则：APS 出计划，MES 做执行；边界清晰，接口对接，禁止把优化引擎塞进 Track  
> 关联：本仓库 MES（Lot / WIP / Equipment / Track / 日后 Dispatch）

---

## 1. 一句话

**APS 回答「在有限产能与约束下，订单/批次该何时、按什么顺序、占用哪些资源」；MES 回答「现场现在能不能动、怎么动」。**

---

## 2. 目标与非目标

### 目标（后续 APS 系统）

| 能力 | 说明 |
|------|------|
| 主计划 / 细排程 | 天～班次～小时级：排什么、何时做、做到哪 |
| 有限产能 | 设备台数、工时、班次、瓶颈机台 |
| 约束满足 | 交期、优先级、换型、齐套、人员资质（按行业加深） |
| 场景推演 | 插急单、设备故障、交期变更 → 重排 What-if |
| 计划下发 | 回写 MES / Dispatch：目标开工窗、建议机台组、优先级 |

### 非目标（明确不做进 MES 主路径）

- 不替代 TrackIn/Out、Hold、履历  
- 不替代实时 Dispatch（此刻选哪台）  
- 不做 SECS/GEM、数采、OEE 本体（可消费其结果）  
- 一期不上全量供应链 APS（需求预测、多工厂协同可后置）

## 3. 大厂怎么做（调研摘要）

### 3.1 业界共识：两套系统、双向数据

| | APS | MES |
|--|-----|-----|
| 层级 | 计划层（偏 ERP 之下、现场之上） | 执行层（车间实时） |
| 时间 | 天 / 班 / 小时，可离线重算 | 秒～分钟，强一致事务 |
| 输入 | 订单、交期、BOM/工艺、产能日历、约束 | WIP、设备态、Hold、实际工时 |
| 输出 | 排程结果、承诺交期、资源负荷 | Track 事务、现场指令、履历 |

常见闭环：

```
ERP（订单/交期）
  → APS（有限产能排程 / 场景推演）
    → MES Dispatch（按计划+实时态选机）
      → Track（开工/完工）
        → 实绩回写 APS（进度、延误、可用产能）
```

Critical Manufacturing 等厂商把 APS 做成与 MES **同主数据、读实时 WIP/设备态** 的模块，强调「计划必须吃现场真相」；多数企业仍是 **独立 APS + 集成总线**。

### 3.2 产品版图（买的时候别比错类）

业界把「APS」拆成两类，混比会导致选型失败：

| 类型 | 做什么 | 代表 |
|------|--------|------|
| **Full-stack 计划** | 需求→供应→库存→主计划→细排 | Kinaxis、o9、SAP IBP+PP/DS、Blue Yonder、Oracle SCP、OMP |
| **Detailed Scheduling** | 车间有限产能细排、换型与序列 | Siemens Opcenter APS / Preactor、Asprova、PlanetTogether、DELMIA/Quintiq |

决策顺序（大厂采购常用）：

1. 只要车间细排，还是要从需求到排程一整条？  
2. 企业级（12～24 月 / 高 TCO）还是中端？  
3. 离散 / 流程 / 特殊约束（半导、炼化等）？

### 3.3 半导场景特点

- 重入工艺、瓶颈机台、Hot Lot、工程批与量产隔离、换型/再认证成本高  
- 韩系等厂有独立 APS 落地案例：把复杂约束做成管理工具，而不是塞进 Track  
- 通用 mid-market full-stack 常注明 **不适合晶圆厂极端约束**；半导要么专用排程、要么 Detailed Scheduling + 自研规则  
- 实时「下一台机」仍属 **MES Dispatch**；APS 管更长窗口的负荷与交期

### 3.4 算法与交互（大厂共性）

- 启发式 / 约束规划 / 元启发式；目标可选：交期达成、稼动、换型最少  
- 甘特 / 负荷图 / 多方案对比；自适应重排（事件触发或定时）  
- 计划版本：草稿 → 发布 → 冻结窗；发布后才允许下发 MES

## 4. 与本项目 MES 的边界

| 本仓库模块 | APS 关系 |
|------------|----------|
| Lot / 优先级 / 交期字段 | APS 主输入；MES 保留执行态 |
| Route | APS 算工序时长与先后；MES 仍用版本快照执行 |
| Equipment / 状态 / 稼动 | APS 读可用产能；Down/PM 触发重排输入 |
| WIP | APS 读在制位置与排队；不反向改 WIP 投影写路径 |
| Track | **不调用** APS；只消费已发布计划（可选校验） |
| Dispatch（待建） | 短周期选机；可把 APS「建议机台组/时间窗」当软约束 |
| Recipe | 后置：资格与换型矩阵进入 APS 约束表 |

```
ERP ──► [APS 独立服务] ──发布计划──► MES（Dispatch / 看板）
                ▲                         │
                └──── 实绩 / WIP / Eqp ────┘
```

## 5. 建议总体架构（后续建设）

```
计划主数据：订单、交期、工艺路径、标准工时、产能日历、约束规则
  → 排程引擎（独立进程/服务）
  → 计划库（方案版本、甘特结果、负荷）
  → 发布 API → MES
  → What-if 沙箱（不污染已发布版）
```

| 组件 | 说明 |
|------|------|
| `aps-service` | 独立部署；可另库 |
| 计划库 | 方案/版本/行项目；与 `mes_lot` 解耦 |
| 集成 | REST / MQ；幂等下发；失败可重试 |
| 权限 | 计划员角色；发布与冻结需审计 |

技术选型后置拍板：自研启发式 MVP vs 嵌入开源/商用引擎；**与 MES 同 JVM 长期混部不推荐**。

## 6. 对本仓库的分期建议

| 阶段 | 内容 | 说明 |
|------|------|------|
| **现在** | 做透 MES：WIP、Equipment、Track、薄 Dispatch | 给 APS 喂干净实绩 |
| **P1** | APS MVP：订单+交期+有限产能+甘特+发布到 MES | 规则/启发式即可 |
| **P2** | 换型、齐套、Hot Lot、事件重排、What-if | |
| **P3** | 多目标优化 / 与 ERP 深度集成 / 半导专用约束 | 视厂型 |

**Dispatch 先做、APS 后做**：先解决「此刻上哪台」，再解决「这周怎么排」。

---

## 7. 与 MES 接口草案（预留，不落地）

| 方向 | 内容 |
|------|------|
| MES → APS | Lot/WIP 快照、Eqp 可用态、标准/实际工时、Hold 占用 |
| APS → MES | `planId`、Lot 计划窗、建议 `eqpGroup`/优先级、冻结标记 |
| MES 行为 | Dispatch 排序加权；可选拒绝严重偏离计划窗的开工（策略开关） |

---

## 8. 风险与原则

| 风险 | 应对 |
|------|------|
| 把 APS 写进 Track | 禁止；计划只读/软约束 |
| 计划与现场脱节 | 强制吃 WIP+设备态；发布短周期滚动 |
| 选型 full-stack vs 细排混淆 | 先定范围再选型 |
| 半导约束被低估 | MVP 先交期+产能+优先级，专用约束单独立项 |

## 10. 结论

1. **APS 是独立计划系统**，大厂以「计划优化 + 与 MES/ERP 集成」交付，而不是 MES 里加一张排程表。  
2. 对本项目：**后续单独立项**；先 Dispatch，再 APS MVP。  
3. 当前 MES 把 Lot/WIP/Equipment/Track 做稳，是以后 APS 最值钱的输入。
