# 半导 MES 知识助理（RAG）方案

> 版本：v0.1（考察稿）  
> 定位：基于历史知识与异常修复方案的问答系统  
> 原则：只检索与建议，不自动改工艺 / 不直接执行 Hold、Skip、Scrap  
> 优先级：P1～P2；排在良率检控与数据闭环之后

---

## 1. 目标

为工艺、设备、质量、现场人员提供：

- 异常怎么排查、怎么处置的可引用回答
- 关联 SOP、历史案例、原因码说明
- 挂在 Alarm / Hold / Lot 上下文旁的「问 AI」入口

**非目标**：替代 SPC/良率检控；直接改 Recipe；未经审核知识当生产指令。

---

## 2. 与现有 AI 能力关系

```
检控 AI ──► Alarm / 建议 Hold
                │
                ▼
         「这类情况怎么处理？」──► 知识助理 RAG
                │
                ▼
         引用 SOP / 历史案例 / 步骤建议
                │
                ▼
         用户确认后走 MES API（Sa-Token 鉴权）
```

| 能力 | 优先级 |
|------|--------|
| 良率检控 / EDC 判异 | P0 |
| 结构化相似 Lot | P1 |
| **知识助理 RAG** | P1～P2 |

---

## 3. 总体架构

```
SOP · 作业指导 · 原因码 · 异常案例 · 审核修复方案
        → 解析/切片/审核入库
        → 文档库(MinIO) + 元数据(MySQL) + 向量索引
        → 检索 → 重排 → LLM → 强制引用来源
        → React 问答框 / Alarm·Hold·Lot 侧栏
```

---

## 4. 知识范围

### 纳入

| 类型 | 要求 |
|------|------|
| SOP / WI | 版本号、生效日期 |
| 原因码说明 | 与字典一致 |
| 异常案例 | 固定模板：症状/排查/处置/结果/审核人 |
| 设备要点、修复方案 | 必须审核 |

### 不纳入

未审核聊天、过期工艺（`obsolete` 默认可检索关闭）、未脱敏机密参数。

### 案例模板

```
案例编号 / 产品·站点·设备类型 / 症状 / 原因码
排查步骤 / 处置动作（仅描述） / 结果是否有效 / 审核人·日期
```

---

## 5. 核心流程

```
提问（可带 lotId/alarmId/holdId）
  → 拉 MES 上下文 → Query 改写 → Top-K 检索 → 重排（权限/过期过滤）
  → LLM 仅基于资料回答 → 答案+来源 → 审计日志
```

无命中：明确「知识库暂无依据」，禁止编造。  
建议动作按钮调原有 MES 接口，助理服务不直接写 Lot 状态。

---

## 6. 检索与生成

- 切片：SOP 按章节 300～800 字；案例整案优先  
- 元数据过滤：site / product_family / eqp_type / step / published  
- 生成约束：必须带来源；冲突并列；改机台/锁批标注需人工确认  
- 可与相似 Lot 结构化检索分区展示

---

## 7. 权限（Sa-Token）

| 权限码 | 说明 |
|--------|------|
| `ai:kb:ask` | 发起问答 |
| `ai:kb:view-source` | 查看原文 |
| `ai:kb:upload` / `publish` / `admin` | 上传、发布、下架 |

问答全量审计；外部 LLM 出厂需脱敏。

---

## 8. 接口草案

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/ai/kb/ask | 问答 |
| POST | /api/ai/kb/docs | 上传文档 |
| POST | /api/ai/kb/cases | 录入案例 |
| POST | /api/ai/kb/docs/{id}/publish | 发布 |
| GET | /api/ai/kb/search | 仅检索（调试） |

响应含：`answer`、`citations`、`suggestedActions`、`grounded`。

---

## 9. 组件选型

MinIO（原文件）+ MySQL（元数据/案例/日志）+ 向量库（Milvus/pgvector 等）+ 独立 RAG 服务 + 私有化 LLM（或脱敏网关）。  

起步可先：**MySQL 案例库 + 关键词检索**，再上向量。

---

## 10. 前端挂载点

全局入口；Alarm/Hold/Lot 侧栏；知识管理后台。答案下方固定「来源」卡片。

---

## 11. 分期

| 阶段 | 内容 |
|------|------|
| K0 | 案例表 + 录入 + 关键词问答 |
| K1 | SOP + 向量 RAG + 强制来源 |
| K2 | 挂 Alarm/Hold 上下文 + 建议动作按钮 |
| K3 | 与相似 Lot、良率告警打通 |
| K4 | 有用/无用反馈驱动治理 |

先用 K0 验证案例能否持续沉淀。

---

## 12. 风险与结论

| 风险 | 对策 |
|------|------|
| 知识太少 | 先模板与流程，再上大模型 |
| 当成自动指令 | UI 标明建议；动作二次确认 |
| 过期 SOP | 版本 + 废止 + 展示日期 |

**结论**：要做知识助理作经验复用；不做生产执行器；先案例审核流，再向量 RAG；与检控互补。
