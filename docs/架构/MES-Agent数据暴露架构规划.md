# MES Agent 数据暴露 — 架构规划

> 版本：v0.1（规划稿，非详设）  
> 定位：对外给 Agent 用的数据/能力暴露方式；后续再做接口与工具清单设计  
> 对齐：`docs/架构/半导MES架构设计.md`；`docs/方案/MES-AI赋能方案.md`  
> 原则：MES API 为真源；Agent 工具挂 Facade；MCP 仅作可选协议适配  
> 状态：**规划立项 · 未实施**  
> 更新：2026-09-18

---

## 1. 目标与边界

**目标**

- 让外部 / 内部 Agent 能安全查询与受控调用 MES 能力（追溯、WIP、告警、报表等）
- 契约稳定、可审计、可版本演进
- 多 Agent 客户端（自建 Agent、Cursor、Claude 等）可复用同一业务能力层

**不做（本期规划不展开）**

- 具体 Tool / MCP method 清单与参数 schema
- Agent 编排、Prompt、RAG 细节（见 AI / RAG 方案）
- 模型直接改 Lot 状态、绕过权限的写操作

**禁止**

| # | 禁止 | 理由 |
|---|------|------|
| P1 | Agent / MCP 直连数据库 | 绕过事务、权限、履历 |
| P2 | 把全部 REST 1:1 映射成工具 | 粒度碎、易打爆库、难治理 |
| P3 | 以 MCP 替代业务 API 作为主契约 | 版本/审计/网关能力弱 |
| P4 | Agent 写路径绕过 Facade / 权限 | 破坏状态唯一真相 |

---

## 2. 核心决策

| # | 决策 | 选择 | 理由 |
|---|------|------|------|
| D1 | 数据真源 | MES 领域 API（Controller → Facade） | 与现有单体模块化一致；鉴权与履历已在路上 |
| D2 | Agent 接入主路径 | Agent 服务封装 **Tool Facade**（按任务聚合调 API） | 自控、低延迟、易审计 |
| D3 | MCP 定位 | **可选适配层**，复用同一 Tool Facade | 多客户端发现/调用协议，不是第二套业务 |
| D4 | 工具粒度 | 任务级（如客诉追溯包、看板概览），非 CRUD 级 | 降调用次数、语义对齐业务 |
| D5 | 写操作 | 默认只读；写必须显式白名单 + 权限 + 审计 | 对齐 AI 赋能「建议不闭环」原则 |
| D6 | 演进顺序 | API 稳定 → Agent Tools →（按需）MCP | 避免双写两套工具定义 |

## 3. 分层示意

```
┌─────────────────────────────────────────┐
│  Agent 客户端（自建 / Cursor / 其他）      │
└─────────────┬───────────────┬───────────┘
              │ 自建协议        │ MCP（可选）
              ▼               ▼
┌─────────────────┐   ┌───────────────────┐
│  Agent 服务      │   │  MCP Server        │
│  Tools 注册/编排  │◄──│  协议壳，无业务逻辑  │
└────────┬────────┘   └─────────┬─────────┘
         │                      │
         └──────────┬───────────┘
                    ▼
         ┌─────────────────────┐
         │  Tool Facade（共享）  │  ← 任务聚合、限流、审计钩子
         └──────────┬──────────┘
                    ▼
         ┌─────────────────────┐
         │  MES API / Facade    │  ← 真源（Lot/Hold/Alarm/History…）
         └──────────┬──────────┘
                    ▼
                 MySQL / 领域服务
```

## 4. 分期（只定方向）

| 阶段 | 内容 | 完成标准（粗） |
|------|------|----------------|
| S0 | 梳理可对外能力边界（读/写白名单） | 有域级清单，无实现 |
| S1 | 稳定对外查询 API（或专用 Query Facade） | Agent 可 HTTP 调通主场景 |
| S2 | Agent 服务 Tool Facade + 鉴权/审计 | 自建 Agent 跑通 1～2 个任务工具 |
| S3 | （按需）MCP Server 挂同一 Facade | 外部 Agent 客户端能发现并调用 |

详设、接口表、Tool schema 本文件不展开，后续单独立项。

## 6. 后续设计时要拍板的项（占位）

- 对外身份：服务账号 / 用户代权 / 两者并存
- 审计落点：`mes_tx_log` 扩展 vs 独立 agent_audit
- 限流与超时：按工具配额还是按调用方配额
- 版本策略：API 版本 vs Tool schema 版本如何对齐
- 首批工具域：History 追溯 / Dashboard / Report / Alarm 查询（待选型）
