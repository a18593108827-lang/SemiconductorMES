# Loop Engineering（循环工程）学习笔记

> 调研时间：2026-09-24　｜　来源：Addy Osmani 原文（O'Reilly Radar 转载）、IBM Think 词条、Machine Learning Mastery、Cobus Greyling 开源仓库及多篇中文解读，均为一手/二手公开资料。
> 这是 [ReAct Agent 学习笔记](../ReAct-Agent/README.md) 的**下一层**：ReAct 讲「一个循环内部怎么转」，Loop Engineering 讲「谁来写这个循环、它何时启动、何时停、怎么证明做对了」。

## 一句话定义

> **Loop Engineering 是把你从「给 Agent 打 prompt 的那个人」替换掉 —— 改为由你设计的系统去打 prompt。**
>
> —— Addy Osmani（Google Cloud AI Director），2026-06-07

这里说的「循环」可以理解为一个**递归目标**：你定义目的，AI 反复迭代直到完成。

| 时间 | 事件 |
|------|------|

| 2026-07 | IBM Think 发布词条，把它纳入企业级 AI 工程术语体系 |

概念的**点火者**是两位实践者，Osmani 只是给它取了名字：

- **Peter Steinberger**："你不该再给编码 Agent 打 prompt 了。你应该设计会 prompt 你 Agent 的循环。"
- **Boris Cherny**（Anthropic，Claude Code 负责人）："我已经不再 prompt Claude 了。我有一堆循环在跑，由它们去 prompt Claude、自己决定做什么。我的工作就是写循环。"

## 四层演进（核心心智模型）

每一层**包裹**前一层，而不是替代它：

| 层 | 优化对象 | 时间 | 核心问题 | 代表 |
|----|---------|------|---------|------|
| ① Prompt Engineering | 怎么**问** | 2022–2024 | 怎样写一条 prompt 才能让模型给出好答案？ | ChatGPT 早期的提示词技巧 |
| ② Context Engineering | 给模型看**什么** | 2025 | 推理那一刻，模型该看到哪些 token？ | `CLAUDE.md` / `SKILL.md` / `AGENTS.md` |
| ③ Harness Engineering | 怎么约束**单次运行** | 2026 初 | 单次运行需要一个什么样的环境？ | Claude Code 的 Hooks 系统 |
| ④ **Loop Engineering** | **谁决定何时再 prompt、结果是否合格** | 2026.06 | 什么循环能让 Agent 持续朝目标工作，以及它**何时该停**？ | `/loop`、`/goal`、Automations |

> **Prompt 工程没有消失——它是 Loop 的组件。Context 工程没有消失——Loop 每一轮仍需正确注入上下文。Loop 新增的是自主控制结构。**

## 五个积木 + 一个记忆

| 积木 | 职责 | 一句话 |
|------|------|--------|
| **Automations** | 心跳 | 按计划自动**发现和分类**任务，不用人去巡 |
| **Worktrees** | 隔离 | 多个 Agent 并行互不踩脚 |
| **Skills** | 知识固化 | 把项目知识写下来，agent 不必每轮重新猜 |
| **Plugins / Connectors** | 触角 | 通过 MCP 接进你真实的工具（issue、DB、Slack） |
| **Subagents** | 制衡 | **一个出主意，另一个来检查** |
| **State / Memory** | 脊柱 | 活在会话之外的状态：markdown 文件或看板 |

> **"The agent forgets; the repo doesn't."**（模型会忘，仓库不会。）所以记忆必须在磁盘上，不在上下文里。

## 一页速记卡

**定义**：定义递归目标 → 设计闭环系统（发现 → 分派 → 执行 → 验证 → 迭代）→ 让循环自己驱动 Agent。

**角色转变**：从「驾驶员」变成「自动驾驶系统的设计师」。

**与 cron 的区别**：调度层确实就是 cron（Boris 字面上就是用 cron 跑循环）；**但 cron 跑固定脚本，loop 的下一步由模型判断**。

**Loop 不是什么**：不是「让 Agent 多跑几轮」。真正的差别是 —— **每一次运行都知道自己为什么开始、能在哪里动手、必须怎么证明结果、什么时候该停、以及下一次该记住什么。**

**最大的坑（务必记住）**：设计 loop 只是工作的一半。**另一半是在 loop 里放进能说「不」的东西** —— 真实的测试、类型检查、编译错误。没有反向推力的循环，只会变成 AI 不断同意自己的装置。
