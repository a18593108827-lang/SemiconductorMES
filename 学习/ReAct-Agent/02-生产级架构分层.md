# 02 · 生产级架构分层

## 2.1 八层架构

一个典型的大厂级 ReAct Agent 分层：

| # | 层 | 职责 | 典型组件 |
|---|-----|------|---------|
| 1 | **接入层** | 对外接口、协议、流式 | API Gateway / WebSocket / SSE 流式输出 |
| 2 | **会话层** | 会话与身份 | Session、Memory、Trace ID、用户权限 |
| 3 | **编排层** | **ReAct 循环本体** | Agent Runtime、ReAct Loop、Router、Planner |
| 4 | **模型层** | 推理与决策 | LLM、Function Calling、小模型路由、推理模型 |
| 5 | **工具层** | 执行外部动作 | Tool Registry、OpenAPI、Lambda、RPC、代码沙箱 |
| 6 | **知识层** | 外部事实来源 | Vector DB、搜索、知识库、RAG |
| 7 | **治理层** | 刹车与合规 | Auth、Policy、Guardrail、审计、限流、HITL |
| 8 | **观测层** | 可回放可评估 | Tracing、Metrics、Logging、Eval、回放 |

分层数据流：

```
用户
 │
 ▼
[1 接入层] ──▶ [2 会话层] ──▶ [3 编排层] ◀───▶ [4 模型层]
                                  │                    ▲
                                  │  工具调用           │ 决策
                                  ├──▶ [7 治理层] ──▶ [5 工具层]
                                  │         │            │
                                  │         │            ▼
                                  └──▶ [6 知识层]   (Observation)
                                  │
                                  └──▶ [8 观测层]（每步埋点）
```

注意：**治理层是"竖切"的**，不是流水线上的一站。每一次 Action 都必须穿过它。

## 2.2 核心循环伪代码

```python
history = [system_prompt, user_input]

for step in range(max_steps):
    out = llm(history, tools=tool_schemas)

    # 1) 终止信号
    if out.type == "final":
        return guardrail(out.content)

    thought = out.thought
    action  = out.action
    args    = out.args

    # 2) 策略闸门：这一步能执行吗？
    if not policy.allow(user, action, args):
        observation = "拒绝：当前用户无权限执行该操作"
    else:
        # 3) 工具网关执行（统一超时/限流/审计/重试/熔断）
        observation = tool_gateway.execute(
            action, args, timeout=3s, trace_id=trace_id
        )

    # 4) 观察压缩后写回上下文
    observation = clean_truncate_summarize(observation)
    history.append({
        "thought": thought,
        "action": action,
        "observation": observation,
    })
```

## 2.3 五个关键设计点（背下来）

### ① LLM 是决策器，不是执行器

它**只输出**「下一步做什么」。绝不把"能直接改数据库/发邮件"的能力交给模型。
好处：模型更换、Prompt 迭代都不会触碰真实的副作用边界。

### ② Tool Gateway 是执行器

所有工具调用必须过网关，由网关统一负责：

- 鉴权（谁能调）
- 限流（调多快）
- 审计（谁调了什么、结果如何）
- 重试 / 熔断 / 降级
- 幂等键（防重复扣款）

### ③ Policy / Guardrail 是刹车

高风险动作（退款、删除、发邮件、回滚、执行 SQL）必须**人工确认**，不由模型自主决定。
刹车要在**编排层**，不在 Prompt 里 —— Prompt 只能"劝"，不能"挡"。

### ④ Trace 是生命线

每一步的 `Thought / Action / Observation / token / 延迟 / 成本` 都要可回放。
没有 Trace，线上问题无法定位，Eval 也无从下手。

### ⑤ 上下文要管理

长 Observation 必须摘要，旧步骤必须压缩 —— 否则上下文线性膨胀，成本与延迟一起爆炸。
（详见 [05 · 工程治理](./05-工程治理-死循环-工具滥用-成本.md) 的成本章节）

## 2.4 一句话总结这一层

> **ReAct 循环只在编排层里跑；模型层出决策，工具层出事实，治理层出边界，观测层出证据。**
