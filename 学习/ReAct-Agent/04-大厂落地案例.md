# 04 · 大厂落地案例

五个阵营，各有侧重。**读的时候重点看"架构启示"那一行** —— 面试和设计时能直接用。

## 4.1 Google：模式发源地 + 平台化

**论文侧**：ReAct 的发源地之一。PaLM-540B 在 HotpotQA、FEVER 上通过 ReAct **减少幻觉**，在 ALFWorld、WebShop 上通过"推理 + 行动"**提升任务成功率**。

**产品侧**：Vertex AI Agent Builder / ADK 支持工具调用、编排、RAG。

典型链路：

```
用户问题 → LLM 推理 → 调用搜索/知识库/API → 观察结果 → 继续推理 → 最终回答
```

> **架构启示**：ReAct 适合需要**外部事实**和**动态决策**的任务，而不是纯生成。

## 4.2 OpenAI：产品化最典型的公司

ChatGPT 的联网搜索、代码解释器、第三方插件，本质都是：

```
LLM 决定调用工具 → 工具执行 → 结果回填 → LLM 继续推理
```

以"分析这份 CSV 并画图"为例：

```
Thought: 需要读取文件
Action: code_interpreter 执行 pandas 读取
Observation: 数据摘要
Thought: 需要画图
Action: code_interpreter 执行 matplotlib
Observation: 图片生成
Final: 返回分析结论和图表
```

**关键贡献**：
- **Function Calling** 让 Action 结构化，不再依赖脆弱的文本解析
- **Assistants API / Agents SDK** 把「循环 + 工具 + 状态 + 追踪」封装成运行时

> **架构启示**：**ReAct 是模式，Function Calling 是接口。** 生产系统要用结构化工具调用替代原始文本 ReAct。

## 4.3 Microsoft：代码场景 + 多 Agent

**GitHub Copilot Agent Mode** —— 典型的代码场景 ReAct：

```
用户：修复失败测试
Thought: 先运行测试
Action: run_tests
Observation: 失败日志
Thought: 定位到 src/foo.py
Action: read_file
Observation: 代码内容
Thought: 修改代码
Action: apply_patch
Observation: 修改成功
Action: run_tests
Observation: 测试通过
Final: 已修复并验证
```

**AutoGen** —— 用多 Agent 对话实现类似的循环：`AssistantAgent` 提议工具调用，`UserProxyAgent` 执行代码/工具，再把结果返回。

**Semantic Kernel** —— `Planner + Plugins`，是「规划 + 行动 + 观察」的变体。

> **架构启示**：代码/运维类 Agent **必须**加沙箱、权限、diff 确认、回滚。ReAct 的 Action 不能裸奔。

## 4.4 AWS：把 ReAct 做成云服务

**Bedrock Agents** 的编排层是公开的 ReAct 风格：

```
用户请求 → Orchestration Prompt → LLM 推理
        → 调用 Action Group（Lambda / OpenAPI）
        → 查询 Knowledge Base
        → Observation 回填
        → 最终响应
```

典型客服用例（和 01 里的例子同构）：

```
用户：我的订单没到
Thought: 查订单
Action: getOrder
Observation: 已发货
Thought: 查物流
Action: getShipment
Observation: 延误
Thought: 查赔偿政策
Action: retrieve_kb
Observation: 延误补偿10元
Action: applyCompensation
Observation: 成功
Final: 已道歉并补偿
```

> **架构启示**：大厂会把 ReAct **封装成托管编排服务** —— 工具用 OpenAPI 描述，权限、日志、追踪全部云化。

## 4.5 国内平台：ReAct 与 Workflow 混用

阿里云百炼、字节 Coze/扣子、腾讯元器等，底层普遍是：

```
LLM + Function Calling + 插件 + 工作流 + 知识库
```

典型场景：

| 场景 | 用到的能力 |
|------|-----------|
| 电商客服 | 查订单、查物流、退换货、补偿 |
| 办公助手 | 查日程、发消息、查文档、生成报告 |
| 运维 AIOps | 查监控、查日志、查变更、触发回滚 |

**共同特征 —— 三路分流**：

| 路径 | 承载 |
|------|------|
| 确定性流程 | **Workflow** |
| 动态探索、长尾问题 | **ReAct Agent** |
| 高风险动作 | **人工确认** |

> **架构启示**：国内平台的工程共识是"**分而治之**"，而不是"什么都交给 Agent"。

## 4.6 横向对照表

| 阵营 | 代表 | ReAct 的位置 | 最大启示 |
|------|------|-------------|---------|
| Google | Vertex AI Agent Builder / ADK | 模式的学术源头 + 平台能力 | 解决"需要外部事实"的任务 |
| OpenAI | 插件 / Code Interpreter / Agents SDK | 产品化 + 运行时封装 | 模式 vs 接口要分清 |
| Microsoft | Copilot Agent / AutoGen / Semantic Kernel | 代码场景 + 多 Agent | 危险动作必须沙箱 + 确认 |
| AWS | Bedrock Agents | 托管编排服务 | 工具 OpenAPI 化、治理云化 |
| 阿里/字节/腾讯 | 百炼 / Coze / 元器 | 与 Workflow 混合 | 确定性走流程、长尾走 Agent |
