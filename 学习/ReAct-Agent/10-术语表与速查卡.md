# 10 · 术语表与速查卡

## 10.1 术语中英对照

| 中文 | 英文 | 含义 |
|------|------|------|
| 推理与行动 | **ReAct** (Reasoning + Acting) | 本笔记主题，LLM 推理与工具行动交替的闭环 |
| 思考 / 行动 / 观察 | Thought / Action / Observation | ReAct 循环的三个基本要素 |
| 工具调用 | Tool Calling / Function Calling | 把 Action 结构化为 JSON Schema 的接口协议 |
| 代理运行时 | **Agent Runtime** | 跑 ReAct 循环、管预算与终止的编排器 |
| 工具网关 | **Tool Gateway** | 工具调用的唯一入口，统一鉴权限流审计 |
| 护栏 | **Guardrail** | 内容与动作的安全边界（输入/输出过滤、拦截） |
| 策略引擎 | **Policy Engine** | 执行前检查用户/参数/环境是否允许 |
| 人在环 | **HITL** (Human-in-the-Loop) | 高风险动作需人工确认 |
| 工具检索 | **Tool RAG** | 用向量检索从海量工具里筛出相关工具 |
| 路由器 | **Router** | 决定任务走哪条路径/哪组工具/哪个模型 |
| 规划器 | **Planner** | 先把任务拆成子任务（Plan-and-Execute） |
| 工作流 | **Workflow** | 确定性流程编排，与 ReAct 互补 |
| 观察压缩 | Observation Compression | 截断 / 裁剪 / 摘要 / 外部化 |
| 幂等键 | Idempotency Key | 防重复副作用（重复扣款等） |
| 熔断 | Circuit Breaker | 连续失败后临时禁用，避免持续损耗 |
| 提示注入 | Prompt Injection | 通过工具结果/用户输入注入恶意指令 |
| 追迹 | **Trace / Span** | 每步的输入输出耗时成本记录，可回放 |
| 离线评测集 | Eval Set | 固定输入集 + 轨迹回放做版本对比 |
| 多代理 | **Multi-Agent** | 多角色协作（Supervisor/Worker 等） |
| 主管 / 工人 | Supervisor / Worker | 主管分派、工人执行的多代理模式 |
| 沙箱 | Sandbox | 代码执行/文件修改/网络访问的隔离环境 |

## 10.2 中英速查：三条"谁负责什么"

| 角色 | 负责 |
|------|------|
| **LLM** | 负责**思考** —— 只输出"下一步做什么" |
| **Runtime** | 负责**刹车** —— 步数、预算、去重、无进展检测、终止 |
| **Tool Gateway** | 负责**治理** —— 鉴权、限流、校验、幂等、审计、熔断 |
| **Trace/Eval** | 负责**可观测** —— 可回放、可评估、可迭代 |

## 10.3 速查：三类问题的护栏清单

**死循环**（6 项）
`max_steps` · 动作哈希去重 · 状态哈希无进展检测 · 预算耗尽 · 工具失败熔断 · 软控制提示

**工具滥用**（7 项）
工具分组 + Tool RAG · 描述精确化 · Schema 参数校验 · 权限策略 · 限流配额 · 幂等键 · 成本标签

**成本失控**（8 项）
硬预算 · 模型路由 · 上下文压缩 · 缓存 · 超时熔断 · 提前终止 · 并行批处理 · 少用多 Agent

## 10.4 速查：选型判定树

```
这个任务步骤能提前穷举吗？
├── 能 ──▶ Workflow（更稳、更便宜、可审计）
└── 不能
     ├── 能先拆成子任务吗？
     │    ├── 能 ──▶ Plan-and-Execute
     │    └── 不能 ──▶ ReAct
     └── 过程中有不可逆副作用吗？
          └── 有 ──▶ 该步骤必须加 HITL
```

## 10.5 速查：八个设计决策

| 问题 | 做法 |
|------|------|
| 工具太多选不准 | 分组 + Router + Tool RAG |
| 观察太长 | 截断 + 裁剪 + 小模型摘要 |
| 模型不按格式 | Function Calling + JSON Mode + 解析重试 |
| 死循环 | max_steps + 重复检测 + 状态哈希 |
| 成本/延迟高 | 小模型路由 + 缓存 + 并行调用 |
| 提示注入 | 结果标记不可信 + 最小权限 + 输出过滤 |
| 高风险动作 | HITL + 审批流 + 沙箱 + 回滚 |
| 不可观测 | Trace + Span + 回放 + Eval |

## 10.6 面试终局句

> ReAct 是 `Thought → Action → Observation` 的认知闭环；
> **生产级 ReAct = Agent Runtime + Function Calling + Tool Gateway + Policy/Guardrail + Memory + Trace/Eval。**
>
> 大厂面试真正想听的是：你不仅知道 ReAct **怎么想**，还知道它**怎么跑、怎么管、怎么省钱、怎么不出事、怎么评估**。
