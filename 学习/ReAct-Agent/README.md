## ⚠️ 先澄清一个概念

| | **ReAct**（本文件夹主题） | **React**（React.js） |
|---|---|---|
| 全称 | **Re**asoning + **Act**ing | 无（是个库名） |
| 领域 | AI Agent / LLM 运行时控制模式 | 前端 UI 框架 |
| 出处 | Google/Princeton 论文《ReAct: Synergizing Reasoning and Acting in Language Models》 | Meta 开源 |
| 核心 | `Thought → Action → Observation` 循环 | 组件化 + 虚拟 DOM |
| 用途 | 让 LLM 动态调用工具、获取外部事实 | 构建网页界面 |

两者**只是名字像**，内容毫无关系。这份笔记讲的是前者。

> 与本项目的关系：MES 的 `INT-0002`（AI 赋能）与已立项的「Agent 数据暴露架构（Tool Facade + 可选 MCP）」正好需要 ReAct 这类运行时模式 —— 本笔记可直接作为该方向的知识底稿。

> **续篇**：ReAct 讲「一个循环内部怎么转」；**谁来写这个循环、何时启动、何时停、怎么证明做对了** —— 见同级目录 [Loop Engineering（循环工程）学习笔记](../Loop工程/README.md)。两者是不同尺度：ReAct 是 Loop 的执行内核。

### ✅ 参考实现已验证

`09-ReActRuntime参考实现.py` 已在 Python 3.13 实跑通过（无第三方依赖，确定性输出），7 个场景全部按预期触发：

| 场景 | 触发点 | 结果 |
|------|--------|------|
| 正常收敛 | — | 3 步调用后输出 Final |
| 重复动作 | 同一 `get_order(123)` 第 3 次 | 第 2 次注入提示，第 3 次强制中止 |
| 无进展 | 换关键词但观察完全相同 | 连续 3 步相同 → 中止 |
| 高风险动作 | `apply_compensation` 未确认 | HITL 拦截 → 模型改走转人工 |
| 参数越界 | `amount=99999` | 网关 Schema 校验拦截 |
| 工具失败熔断 | `run_sql` 连续失败 2 次 | 第 3 次直接返回"暂不可用" |
| 缓存命中 | 相同工具 + 相同参数 | 实际执行 1 次，命中 1 次 |

> 落地时还修正了原始伪代码里的 **3 处缺陷**（动作去重的 off-by-one 会导致无限注入提示、熔断判断位置偏后、无进展提示重复堆积），详见该文件头部说明。

## 🎯 一页速记卡

**一句话定义**

> ReAct 是 Agent 的**最小认知闭环**：把 LLM 的推理能力与外部工具的行动能力交替起来，形成 `Thought → Action → Observation` 循环，直到任务完成。

**生产级公式**

```
生产级 ReAct = Agent Runtime + Function Calling + Tool Gateway
             + Policy/Guardrail + Memory + Trace/Eval
```

**三个"谁"（最重要的心智模型）**

| 角色 | 职责 |
|------|------|
| **LLM** | 负责**思考**：只输出"下一步做什么"，不直接执行 |
| **Runtime** | 负责**刹车**：步数、预算、去重、无进展检测、终止 |
| **Tool Gateway** | 负责**治理**：鉴权、限流、校验、幂等、审计、熔断 |

**选型口诀**

| 场景 | 选择 |
|------|------|
| 确定流程、强合规、高频业务 | **Workflow** |
| 复杂但可分解的任务 | **Plan-and-Execute** |
| 路径不确定、需要外部事实、动态决策 | **ReAct** |
| 高风险动作（退款/删除/回滚/发邮件） | 加 **HITL**（人工确认） |
| 工具太多选不准 | **Tool RAG** / 分组 + Router |
| 上下文爆炸 | 摘要 + 裁剪 + 外部化 |
